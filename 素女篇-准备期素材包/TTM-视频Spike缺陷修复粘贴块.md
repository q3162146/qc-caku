【缺陷修复｜视频生命周期 Spike 的 2 个 Bug（WASM 实测）】

背景：视频生命周期 Spike 在 WASM 预览已能真实播放视频，且三档码率（low/mid/high）全部 onReady、Seek(3.5)=3.500 精度精确、同屏 3 播放器全部就绪、建销×3 归零、E 三步状态机（CREATING→WAIT_READY→REQUEST_SEEK→WAIT_SEEK_CONFIRM→PAUSED_AT_TARGET→REVEAL）完整通过、视频中文标题「素女篇·视频链路测试」渲染正常。但实测日志暴露 **2 个 Bug**，请修复并复测。

## Bug 1｜A 场景死循环（onPlay 反复触发 Seek，无防重入守卫）

**现象**（log 计数）：
- `onPlay #=2003`、`A onPlay：发起 Seek(3.5)=1994`、`A 确认完成=1920`、`A 继续播放至结尾=1927`、`onPause=1922`。
- 即 A 场景里「Play → Seek(3.5) → 确认完成(3.500) → Pause → 继续播放至结尾 → onPlay → 又 Seек(3.5) → …」**反复循环约 2000 次**，直到视频自然播到结尾触发 `onEnded` 才结束 A。

**根因（推测）**：`onPlay` 回调里**无条件**再次发起 `Seek(3.5)`；`继续播放至结尾` 调用 `Play()` 后 `onPlay` 再次触发 → 再次 Seek → 循环。缺少「本次播放我已发起过 seek」的防重入守卫。

**期望修复**：
- 增加「只发起一次 Seek」的相位/守卫（例如 `seekIssued` 或 phase 状态：仅初次播放时发起 Seek(3.5)，确认完成后 Pause，恢复播放时不再重新 Seek）。
- 让 A 场景序列为「onReady→Play→Seek(3.5)→onTimeUpdate 双确认→Pause→恢复播到结尾→onEnded→销毁」。

**验收**：A 场景 `onPlay` 应为个位数（1~3），`发起 Seek`=1 次，`确认完成`=2 次（双确认），且能正常到达 `onEnded`。不得出现上千次的循环。

## Bug 2｜onTimeUpdate 一次都没触发

**现象**：`onTimeUpdate=0` 次，而 `onReady/onPlay/onPause/onEnded` 均正常触发。当前实现用「轮询 GetCurrentTime」确认 seek（`A 确认完成 | GetCurrentTime=3.500`），并未借助 `onTimeUpdate`。

**期望/需明确**：
- 若 intent 是「播放进度用 widget 的 `onTimeUpdate`（约 10 次/秒、|time−lastUpdate|>0.1 节流）」→ 请把 widget 的 `onTimeUpdate` 回调接上，并确认播放中它确实被触发（能读到 `time/duration`）。这是「回调全部触发」验收项的一部分。
- 若 intent 是「seek 确认不靠 onTimeUpdate、只用轮询 GetCurrentTime」→ 请**明确记录**这一点，并在汇报中说明：`onTimeUpdate` 因实现未使用而未触发（而不是引擎没触发）。但即便如此，正常播放中 widget 的 `onTimeUpdate` 仍应被触发（除非未传该回调）——请核实到底是「没传回调」还是「传了但引擎没回调」。

**验收**：播放中 `onTimeUpdate` 能被触发（>0 次，且带 time/duration）；或明确书面说明为何不触发，并给出结论。
