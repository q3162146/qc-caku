# 22-技术规格确认（TTM 八问结论基线）

> 来源：2026-08-20 TTM 对《8-19开工速查》⑥八问的答复（对照引擎文档/类型声明/示例/设计文档）。
> 状态标记：✅已确认（官方封装明确存在）｜⚠️未确认（需 TapTap 制造预览或真机验证）｜建议（工程策略，非平台硬性上限）。
> 用途：S6 视频接入 / S8 存档读档 / 素材生产（Seedance 生成与转码）的规格基线；真机验证后回写本文件。

## 1. 视频接入方式

| 方案 | 用途 | 结论 |
|------|------|------|
| **A. urhox-libs/Video 的 Video.VideoPlayer（UI 组件）** | 剧情视频 S1~S9 ✅ 首选 | 进 UI 控件树、可叠字幕/跳过/遮罩/任务提示、objectFit=cover/contain、回调齐全、显式 Destroy() |
| B. 原生 VideoPlayer + raw NanoVG | 纯 NanoVG 管线项目 | 需自管每帧 Update/GetTexture/句柄/释放；素女篇不采用 |
| C. VideoScreen3D（3D 视频屏幕） | 场景内投影（石碑幻象/屏幕） | 适合场景投影，**不作为 S1~S9 全屏剧情默认方案** |

## 2. 视频格式与码率（⚠️ 上限无官方规格，以下为兼容性优先测试起点）

- ✅ 明确出现：**MP4 / H.264**
- 首轮验证规格：容器 MP4｜视频 H.264/AVC｜像素 yuv420p｜音频 AAC-LC 48kHz 立体声｜30fps｜关键帧间隔约 1~2s｜竖屏 1080×1920
- 码率三档实测：低 3–4 Mbps（低端机/弱网）｜中 6–8 Mbps（剧情首选候选）｜高 10–12 Mbps（清晰度收益）
- ⚠️ 未确认：容器白名单、Profile/Level 上限、音轨编码白名单、最大码率/帧率/分辨率、移动端与 PC/WASM 差异、色彩格式/GOP/B 帧限制
- **行动：Seedance 生成后统一转码为上述规格再导入；目标设备回归后才转正为项目规范**

## 3. 自定义字体与生僻字

- ✅ 自定义 TTF 可接入（UI.Init fonts 配置；.otf 未同等确认 → 优先转 TTF）
- ⚠️ 生僻字风险：字体缺字形会显示方框/空白；**不能假设自动汉字 fallback 完整可靠**
- **字体分工**：章节名/碑文/结局题词 → 书法体（须预检完整字表）；对话/字幕/札记 → 覆盖完整的宋/楷/黑体；数字/按钮/调试 → 正文字体
- **行动：生成《23-项目字符集》→ 最终字体逐字检查；极少数缺字形用预生成题词图，勿把整段对话转图片**

## 4. 结局分享卡

- ✅ `graphics:TakeScreenShot(Image)` → `image:SavePNG/SaveJPG/SaveWEBP`（写应用可写沙箱相对路径）
- ⚠️ 未确认：保存到手机相册、tap.share、系统分享面板、分享到 TapTap 动态；WASM 文件系统刷新后可能丢失
- **降级方案（不阻塞主线）**：先准备三张预生成结局卡；游戏内 UI 展示；真机验证截图/分享可用再升级为运行时生成；分享不可用则保留卡片预览 + TapTap 发布页引导

## 5. 音频格式

- ✅ 引擎声明支持：**WAV / OGG Vorbis / MP3 / RAW PCM**
- ⚠️ 无明确声明：AAC / M4A / FLAC / Opus
- 推荐：短 UI/SFX → WAV；环境循环/BGM → OGG Vorbis；长配音 → OGG 或 MP3（真机比首播延迟）
- 音频类别：SOUND_EFFECT / SOUND_AMBIENT / SOUND_VOICE / SOUND_MUSIC
- 真机验证项：人声/BGM/SFX 同播、BGM 循环边界、后台回前台音画同步、长语音首播延迟、音源抢占

## 6. 竖屏 9:16（🔴 当前项目是横屏，与设计不一致）

- 🔴 **当前 `.project/project.json` 为 `"screen_orientation": "landscape"`**
- ✅ 引擎声明有 `graphics:SetOrientations(...)` / `GetOrientations()` + OrientationChanged/ScreenMode 事件，**但合法取值未确认，不能猜**
- ⚠️ `tap.setDeviceOrientation` 在当前工作区（引擎文档/类型声明/示例/项目代码）**均未找到**，不能当作本项目 API
- **行动（S1 骨架内一并完成）**：改发布元数据 `screen_orientation: "portrait"` + 实测运行时是否需要 `SetOrientations`；两层都验证后才算锁定竖屏
- 其他：`graphics:SetMode()` 已禁用；9:16 UI 用 urhox-libs/UI 响应式布局；视频 objectFit=cover/contain；目标 1080×1920 但**不要用物理分辨率硬编码 UI 坐标**

## 7. Seek / 暂停 / 多播放器

- ✅ `player:Seek(timeSec)/Pause()/Play()/Stop()`、`GetCurrentTime()/GetDuration()/IsReady()/IsPlaying()`
- ⚠️ **不要假设 Seek() 返回即画面到位**；无独立 Seek 完成事件
- 多播放器代码层可创建（官方 3D 示例多屏幕），**平台上限未知** → 维持设计约束：
  - 正常剧情只保留 1 个；剧情视频 + 循环背景最多 2 个
  - 切换前先销毁旧剧情播放器；循环背景能用粒子/静态图就不占视频实例
  - 播完不只 Stop()，还要 **Destroy()/Dispose()**；真机记录实例数/内存峰值/释放回落

## 8. 事件回调与三步恢复状态机

- UI 组件回调：`onReady`（解码器/首帧就绪）｜`onPlay`｜`onPause`｜`onEnded`｜`onTimeUpdate`｜`onLoadError`
- ⚠️ 无独立 `onDecoderReady/onFirstFrameAfterSeek/onSeekCompleted`；onReady ≠ 每次 seek 完成
- **读档恢复状态机（S8 实现规范）**：
  ```
  CREATING → WAIT_READY(IsReady) → REQUEST_SEEK(Seek(target))
  → WAIT_SEEK_CONFIRM(|cur-target|≤0.15~0.25s 且连续两次确认) → PAUSED_AT_TARGET(Pause)
  → REVEAL(移除遮罩)
  ```
  - 恢复顺序：黑/章节图遮罩 → 建播放器 → onReady → Seek(target) → 轮询时间 → 到位 → （按存档状态）Pause → 移除遮罩

## 9. 后台 / 前台 / 通知栏

- ✅ 事件：`AppWillEnterBackground / AppDidEnterBackground / AppWillEnterForeground / AppDidEnterForebackground`（⚠️ 类型声明实际拼写如此，勿自行改）＋ `AppTerminating / AppLowMemory`；另有 Focused/Defocused 等（不等同通知栏返回）
- ⚠️ 视频模块**不保证**后台自动暂停/释放/回前台恢复 → 项目自管
- 策略：进后台记录 node/video/breakpoint/timeSec + 播放/暂停状态 → 暂停视频/BGM/配音 → 内存测试决定保留或销毁（AppLowMemory 直接销毁可重建媒体）；回前台不直接 Play()，检查 IsReady → 失效重建 → 三步 Seek 恢复 → 恢复字幕/音频 → 按后台前状态决定继续/暂停 → 移除遮罩
- ⚠️ 通知栏返回是否触发完整前后台事件：**第一次真机就记录日志确认**

## 当前最重要结论（开发前置）

1. 剧情视频用 `Video.VideoPlayer`；3D 投影才用 `VideoScreen3D`
2. MP4/H.264 是唯一明确兼容格式；完整编码/码率上限无官方规格 → 按本文件 §2 转码
3. 自定义 TTF 可接入，生僻字必须用项目字表实测（见《23-项目字符集》）
4. 截图保存可用；手机相册/系统分享未确认 → 预生成分享卡降级
5. 音频支持 WAV/OGG/MP3/RAW
6. 🔴 **当前项目为横屏，须在 S1 骨架内改竖屏并双层实测**
7. Seek/暂停支持；无独立 seek 完成事件 → 用当前时间确认
8. 播放器 ≤2 个、播完 Destroy、循环背景优先粒子/静态图
9. 有前后台事件但视频不自动恢复 → 按 §9 策略自管

> 真机验证场景（下一步）：短视频、两播放器、竖屏、字体、音频、后台恢复、截图能力 → 通过后批量接入 S1~S9。
