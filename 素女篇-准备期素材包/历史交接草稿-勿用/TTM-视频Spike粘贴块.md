【B｜视频生命周期 Spike（独立实验任务）】

背景：为 S6 视频接入做技术验证。本项目规划 9 段剧情视频（S1~S9，断点表见《21》§5）。本轮不做正式剧情接入，只做最小生命周期实验，验证《22》§2 的 MP4/H.264 规格是否被引擎接受、事件回调与 seek 精度是否满足断点恢复契约。

素材：项目 `assets/Videos/` 下应有 3 个测试视频（已按《22》§2 规格本地生成并 ffprobe 验证）：

| 文件（资源根下一级路径） | 规格 |
|---|---|
| Videos/S1_test_low_3Mbps.mp4 | MP4 / H.264 High / yuv420p / 1080×1920 / 30fps / 关键帧约1s / AAC-LC 48kHz 立体声 / 10s / 低码率档 |
| Videos/S1_test_mid_6Mbps.mp4 | 同上，中码率档 |
| Videos/S1_test_high_10Mbps.mp4 | 同上，高码率档 |

三支均带画面时间码叠字（`T: HH:MM:SS.mmm F:NNN`）与中文标题，用于 seek 精度目测。若在项目里看不到这些文件，说明素材未上传，请明确告诉我；可先用你自己的短 MP4 验证生命周期，但须注明来源差异。

必读（权威参考）：
1. 引擎视频指南 `engine-docs/recipes/video.md` —— **必须使用 `Video.VideoPlayer` Widget**（`require "urhox-libs/Video"`），禁止裸搓 C++ VideoPlayer + NanoVG 手动渲染。
2. 示例 `examples/19-video-player-ui.lua`。
3. 《22-技术规格确认-八问基线》§2（格式与码率档）。
4. 《21-互动影游双案例应用清单》§5/§6（断点表、两类视频恢复策略、≤2 播放器）。

实现要求：
1. 新建独立实验模块（如 `scripts/experiments/VideoSpike.lua`），用调试键或入口参数触发；**不修改** Chapters / FlowController / 正式剧情流程。
2. 用 `Video.VideoPlayer` 至少加载 mid 档测试视频，`objectFit="contain"`。
3. 完整生命周期并打日志（`print("[VideoSpike] ...")`）：
   - 创建 → `onReady`（解码器就绪、首帧可用）→ Play；
   - 播放中 `Seek(3.5)` → 利用 `onTimeUpdate(self, time)` 连续两次确认 `|当前时间 − 3.5| ≤ 0.15`（两次都通过才判定"已到达目标"）→ Pause；
   - 记录 `GetCurrentTime()` / `GetDuration()` 精度；
   - 播放到结尾触发 `onEnded` → 显式释放（参考视频指南的 Destroy/Dispose 方式）；
   - 重复创建/销毁 3 次，记录播放器实例数量是否归零。
4. 三步恢复状态机最小实现（存档契约第 9 条）：`CREATING → WAIT_READY → REQUEST_SEEK → WAIT_SEEK_CONFIRM → PAUSED_AT_TARGET → REVEAL（移除遮罩）`。用"等待 3 秒 → seek 到 2.0s → 连续确认 → 显示画面"模拟一次读档恢复。
5. 播放器数量上限验证：尝试同屏创建 3 个 VideoPlayer，记录实际行为（成功/排队/报错/内存），确认本项目"同时 ≤2 实例"策略是否可行。

汇报格式（输出给我）：

| 验证项 | 结果 |
|---|---|
| 三档码率（low/mid/high）是否全部被接受播放 | |

| Seek(3.5) 精度：确认时的当前时间、两次确认差值 | |
| 同屏 3 播放器行为（报错/排队/内存） | |
| 销毁后播放器实例数量是否归零 | |

最后给出结论：是否满足《22》§2 规格、S6 能否按此规格接入 13 段断点视频（《21》§5）、遗留风险清单。
